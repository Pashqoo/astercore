# Правила работы в Astercore

Перед работой прочитать `.cursor/rules/assistant.mdc` и `.cursor/rules/memory.md`. Соблюдать
правила из них и тематических файлов памяти, относящихся к задаче (`protocol.mdc` — wire-контракт
терминала, `aster.mdc` — репозиторий и решения, `trading.mdc` — торговля).

**В `trading.mdc` два слоя, и путать их нельзя:** раздел «Aster: механика биржи» проверен
замерами, всё остальное помечено `ПЕРЕНЕСЕНО` — это семантика MoonBot из TInvestCore, на Aster
ещё не проверявшаяся. Снимать пометку только после живой проверки, по одной секции.

Ядро Aster для MoonTerminal по MoonProto. Постановка, замеры и вехи — `PLAN.md`; его читать первым.

Соседний проект `../TInvestCore` — то ядро, из которого это адаптировано. **Его не править ни одной
строкой**, читать можно и нужно: `src/server/` в обоих репозиториях держится текстуально близко
специально, чтобы починка кодека переносилась между ядрами диффом.

`../moon-terminal` — чужой проект, править нельзя. Из него читаются только факты о том, как
терминал понимает ядро (`crates/moon-core/src/venue.rs`, `symbol/mod.rs`, `market/source/read.rs`).

## Commands

Разработка на Mac, `cargo` в `~/.cargo/bin`: `export PATH="$HOME/.cargo/bin:$PATH"`.
Проверено 01.10 — каждая из этих команд прогнана.

- build: `cargo build --release -p aster-core --all-targets`
- test: `cargo test -p aster-core --all-targets` и `cargo test -p moonproto --lib -- server::`
  — наша часть вендора. Без второй команды правка в `server/codec/` проверяется только через ядро.
  Клиентские тесты апстрима (`client::tests::service_cmd_tests`) падают пачкой из-за общего
  состояния между тестами — поодиночке зелёные, дерево не наше, не чиним.
- lint: `cargo clippy -p aster-core --all-targets --no-deps -- -D warnings`
- format: `rustfmt --edition 2021` изменённых файлов в `crates/aster-core` и
  `crates/moonproto/src/server/`. Один прогон **перед** сборкой, не хуком на каждую правку.
- vendor check: `tools/check-vendor.sh` — обязательно после любой правки в `crates/moonproto/`.
  Инвариант: от апстрима на `MOONPROTO_REV` отличаются **только** `src/server/**` и две строки
  хука в `src/lib.rs`. Хук стоит **внутри блока `pub mod`, сразу после `pub mod time;`, без пустой
  строки** — это не вкусовщина: allow-list скрипта сопоставляет ровно эти две строки, и пустая
  строка рядом валит проверку на чистом дереве (поймано 01.10).
- vendor sync: `tools/sync-moonproto.sh` — читает rev из `../moon-terminal/Cargo.lock`.

### Вендорный rev — открытый вопрос

`MOONPROTO_REV` = `2e67562f…` (05.09), тот же, что у TInvestCore. **Терминал пинит `6a6c4199…`
(19.09), на 6 коммитов новее**: 42 файла, +1894 строки в `src/`, включая `src/lib.rs`, куда и
вставляется хук. Решение в `PLAN.md`, «Открытые решения». Пока не решено — не синкать молча: `src/server/` писан
против старого rev.

## Secrets

- `asterkey*` — ключи API биржи (`.gitignore` закрывает `asterkey*`, `*.key`, `*secret*`, `*.env`).
  **Содержимое этих файлов не читать и не печатать**, в журнал не выводить. Имя `asterkey` не
  покрывалось шаблоном `*.key` — дыра закрыта 01.10, до того как в файл что-то положили.
  С 01.10 в файле лежат **тестовые** ключи, боевые трейдер создаст ближе к деплою. Смена ключей
  кода не меняет. Схема подписи по ним выяснена — **v3, EIP-712** (адрес API-кошелька + приватный
  ключ EVM), `PLAN.md`, «Открытые решения» п. 1.
- `aster-core.key` (появится в M0) — ключ подключения терминала к ядру: `master_key` + `mac_key`.
  Это секрет: кто его имеет, тот торгует этим счётом. Права 600, генерируется ядром.
- `data/config.json` (появится в M4) — внутри токен телеграм-бота и пароль страницы. Права 600,
  в журнал не попадает.
- Подпись запросов (`aster/sign.rs`, M2) — единственное место, где секрет превращается в заголовок
  или в подпись. Ни ключ, ни секрет, ни подпись не логируются ни на одном уровне.
- Плейнтекст ключей легитимно живёт только в памяти процесса между чтением файла и формированием
  запроса. Наружу уходит либо `X-MBX-APIKEY` (v1), либо EIP-712-подпись (v3) — сам секрет никогда.

## Канал наблюдения (§7)

Верификация у GUI-ядра не бывает «по коду». Что есть сейчас и чем пользоваться:

1. **`./target/release/aster-core`** — на этой вехе печатает `clock:`, `limits:` и `catalog:` по
   живой бирже. Это проверка REST-пути и отображения каталога целиком.
2. **Перекрёстный замер.** Любое число из `catalog:` сходится с независимым разбором
   `/fapi/v1/exchangeInfo` (питон в скрэтчпаде): **596 USDT-перпов + 0 неперпетуальных + 17 по
   квоте = 613**. Ноль во втором слагаемом — не опечатка: дат-фьючерсов у Aster нет вовсе, а пять
   символов с пустым `contractType` — это пять пред-листингов, и они в каталоге. Было «591 + 5»,
   пока пустое значение ошибочно считалось не-перпетуальным. Расхождение здесь — дефект
   отображения, а не «биржа изменилась».
3. **Контрактный тест на loopback** (M0): поднять наш сервер и подключить `moonproto::MoonClient`
   того же rev — он и есть терминал в миниатюре.
4. **Сам терминал** (M1+): скриншот кадра. Стакан и чарт по коду не выводятся.
5. **Эмулятор** (M3) — заход стратегии при нулевом денежном риске. На Aster это важнее, чем было
   на MOEX: песочницы под боевую подпись у нас может не быть (`PLAN.md`, «Открытые решения» п. 1).

`MIN_NOTIONAL` на всех символах = 5 USDT, значит живая проверка ордера стоит пять долларов.
